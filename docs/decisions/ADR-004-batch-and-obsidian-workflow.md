# ADR-004：批量归档与 Obsidian 输出采用分层、顺序和可选策略

## 状态

Accepted，实施尚未开始。

## 日期

2026-09-01

## 背景

v0.2 已能安全地转换单个 OOXML 文件，但个人知识库归档需要一次处理多份文件、了解逐项结果，并按需要生成 Obsidian 元数据。方案必须保持纯本地、默认输出兼容、无绝对路径泄露和原子发布。

## 决定

1. 增加独立的 `BatchConversionService`，按顺序复用 `ConversionService`；不把批处理循环放入 UI 或格式适配器。
2. 队列状态使用稳定模型：待处理、转换中、成功、警告、失败、跳过、取消。
3. v0.3 使用一个后台工作线程，Tkinter 主线程通过线程安全事件队列更新界面。
4. 取消只在下一个任务开始前生效；正在执行的解析不承诺强制中断。
5. Obsidian frontmatter、标签、相对来源链接和原文件复制都经 `ConversionOptions` 显式启用；默认关闭。
6. YAML 使用受控序列化，来源链接必须相对且经根目录包含校验；禁止输出绝对输入路径。

## 备选方案

### 在 UI 中直接循环调用转换

- 优点：初始代码较少。
- 缺点：UI 阻塞、错误恢复和单元测试困难，无法复用给未来命令行或自动化入口。
- 结论：拒绝。

### 并发处理队列

- 优点：多核机器可能更快。
- 缺点：输出冲突、内存峰值、进度和取消语义显著复杂，个人归档场景暂未证明需要。
- 结论：延后，性能样本证明需要时再评估。

### 默认启用 Obsidian 元数据和复制原文件

- 优点：首次输出更接近完整 vault 条目。
- 缺点：改变现有用户的输出内容，可能增加隐私暴露和磁盘占用。
- 结论：拒绝，改为显式选项。

## 后果

- 单文件转换保持可独立测试、事务性与向后兼容。
- 批量部分可以测试扫描、状态、冲突、取消和部分失败，而不依赖桌面 UI。
- 需要增加 YAML/路径安全、线程事件和批量汇总测试。
- 后续并发或其他 UI 宿主可在不改动解析器的前提下替换调度层。
