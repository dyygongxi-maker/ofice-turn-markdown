# Problems and Risks

## PR-001：Markdown 与复杂 Office 页面不等价

- 状态：已知设计限制。
- 根因：Markdown 是线性语义标记，不包含任意页面坐标、动画或嵌入对象模型。
- 处理：优先导出语义内容和静态资源，所有不能可靠映射的元素进入转换报告。
- 预防：使用真实样本的人工对照测试，禁止将输出宣传为无损还原。

## PR-002：Excel 公式值未必可取得

- 状态：待技术验证。
- 根因：OOXML 文件可能不含最近保存的计算缓存，解析库也不负责执行 Excel 公式。
- 处理：保存公式文本；缓存值缺失时明确报告，不生成伪造结果。
- 预防：测试样本覆盖有缓存与无缓存两种工作簿。

## PR-003：浏览器宿主与本地输出目录选择冲突

- 状态：已解决；ADR-003 已接受。
- 根因：浏览器基于安全模型限制任意本地目录写入，无法把输出目录选择作为跨浏览器可靠能力。
- 处理：推荐改用 Windows 原生桌面 UI，直接调用本地文件和目录选择器；核心保持与 UI 无关。
- 预防：涉及本地文件读写的产品流程，在设计阶段先验证宿主平台的权限模型与输出交付方式。

## PR-004：项目尚无独立 Python 环境与锁定依赖

- 状态：已解决。
- 根因：系统 `python` 与 `py` 命令均不在 PATH；虽然 Codex 受控运行时可导入候选库，但它不应作为项目可复现环境。
- 处理：已在项目目录创建独立虚拟环境，使用 `pyproject.toml` 声明依赖并以 `requirements.lock` 记录验证版本。
- 预防：在任何项目代码或样本生成前，建立项目本地环境和可复现依赖清单。
- 备注：样本清单使用 JSON，以 Python 标准库校验，不额外引入 YAML 解析依赖。

## PR-005：Tkinter 无法进入 Windows 分发产物

- 状态：已解决，Windows 分发产物已验证启动。
- 根因：PyInstaller 检测到当前 Python 环境的 Tcl/Tk 安装损坏并排除 `tkinter`，而桌面应用在启动时导入它；此外，直接以包内 `__main__.py` 作为入口会失去相对导入上下文。
- 处理：新增顶层绝对导入启动器，并将 UI 宿主替换为可随应用分发的 `PySide6-Essentials`；核心转换层保持无 UI 依赖。
- 预防：每次变更桌面运行时或入口后，必须等待 PyInstaller 的 `Build complete!` 与 `COLLECT` 阶段结束，再检查新 exe 时间戳、警告文件和实际启动结果；不得把错误对话框仍在显示时的进程存活误判为启动成功。

## PR-006：Qt 绑定 DLL 的目录布局不满足 Windows 加载器

- 状态：已解决，干净 Windows 分发产物已验证启动。
- 根因：PyInstaller 默认将 `shiboken6.abi3.dll` 放入 `_internal\\shiboken6`，但 `PySide6\\pyside6.abi3.dll` 由 Windows 加载器加载时只会在其自身目录及已注册目录中查找依赖，因而无法解析该 DLL，导致 `QtWidgets` 导入失败。
- 处理：构建脚本显式将 `shiboken6.abi3.dll` 作为二进制文件收集到 `_internal\\PySide6`；增加回归测试验证此打包规则。
- 预防：所有含原生扩展的桌面依赖都要检查直接 DLL 依赖与最终目录布局，且必须从干净 `dist` 目录启动验证。
