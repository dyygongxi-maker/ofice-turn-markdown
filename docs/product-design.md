# 产品设计：廾匸转换 v0.3 知识库归档增强版

**状态：** 已规划，尚未实现
**日期：** 2026-09-01
**前置版本：** v0.2 本地单文件转换 MVP

## 1. 目标与范围

廾匸转换帮助个人用户在 Windows 本机将标准 `.docx`、`.pptx`、`.xlsx` 文件归档为适合 Obsidian 和 AI 阅读的 Markdown。v0.3 聚焦把已可用的单文件转换扩展成可管理、可追溯的知识库归档流程。

本版本规划四项能力：

1. 批量转换与文件夹队列。
2. 转换结果页与可操作报告摘要。
3. 可选的 Obsidian 归档模式。
4. 复杂 Office 文件的能力声明、警告检测和渐进式兼容性增强。

当前 MVP 仅支持单文件选择、单文件转换、Markdown/资源/报告输出。本文所述 v0.3 功能均为规划目标，不表示已经交付。

## 2. 用户与成功标准

主要用户仍为个人用户。典型任务是把一批历史 Word、演示文稿和表格放入本地知识库，之后可在 Obsidian 检索、链接或交给 AI 阅读。

成功标准：

- 用户可从多文件或一个文件夹建立可审阅的转换队列。
- 单项失败、跳过或警告不会中断其他任务，也不会留下半成品输出。
- 用户在任务结束后能找到每项输出目录和转换报告。
- 选择 Obsidian 模式时，输出具备稳定、可读且不泄露绝对路径的元数据与相对链接。
- 对复杂元素，产品明确说明“支持、降级、仅报告或拒绝”，不暗示无损还原。

## 3. 用户流程

```text
选择多个文件或文件夹
  -> 预览并确认队列
  -> 后台顺序转换
  -> 汇总结果页（成功、警告、失败、跳过、取消）
  -> 打开受控输出目录/转换报告，或在 Obsidian 中继续整理
```

### 3.1 批量与文件夹队列

- 支持多文件选择和文件夹扫描；仅纳入 `.docx`、`.pptx`、`.xlsx`。
- 文件夹扫描是否递归由用户选择，默认不递归，以避免意外处理大量资料。
- 每项显示来源、格式、输出目标与状态：待处理、转换中、成功、警告、失败、跳过、取消。
- 默认不覆盖既有输出；目标冲突作为“跳过”并说明原因。
- 单项错误不终止整批任务；失败信息只显示安全、简明的错误摘要，不显示文档正文。
- 首版按顺序执行，取消在下一个任务开始前生效；不承诺中断正在被第三方解析库读取的文件。

### 3.2 结果页

- 显示总数及成功、警告、失败、跳过、取消数量。
- 列出每项的最终状态、警告代码或安全错误摘要。
- 对成功或警告项提供“打开输出目录”和“打开转换报告”。
- 不提供任意路径启动；只能打开本次转换产生的受控目录和报告。

### 3.3 Obsidian 归档模式

Obsidian 模式是可选项，默认输出协议不变。用户可选择：

- 在指定的 vault 根目录下输出。
- 在 Markdown 文件加入 YAML frontmatter。
- 写入经过校验的标签。
- 加入原文件的相对链接。
- 选择是否复制原文件，默认关闭。

示例：

```yaml
---
source_file: "示例.docx"
source_format: docx
converted_at: "2026-09-01T20:00:00+08:00"
converter: "廾匸转换"
warnings:
  - XLSX_FORMULA_CACHE_UNAVAILABLE
tags:
  - inbox
  - office-import
---
```

原文件链接只使用相对路径，不能写入用户的绝对磁盘路径。开启转换时间后，元数据会随执行时间变化；正文与资源命名仍应稳定可重复。

### 3.4 复杂文件兼容性

兼容性提升先建立真实或脱敏回归样本和能力矩阵，再逐格式增加支持。

| 格式 | 优先支持 | 降级或报告 |
| --- | --- | --- |
| DOCX | 超链接、编号/多级列表、复杂表格、图片顺序 | 浮动对象、复杂样式与不可稳定定位元素 |
| PPTX | 两栏文本、备注、表格、组合形状的基础文本 | 重叠形状、图表、OLE、SmartArt、音视频 |
| XLSX | 隐藏行列、多区域表、合并单元格与空白分隔 | 图表、透视表、公式重算与复杂视觉格式 |

每种能力必须标明支持级别，并有对应样本和警告/结构断言。无法可靠保留的信息进入报告而非静默丢弃。

## 4. 不在 v0.3 范围内

- WPS 原生 `.wps`、`.et`、`.dps` 与旧版 `.doc`、`.xls`、`.ppt`。
- OCR、PDF 转换、公式计算、宏执行、云同步、账户、协作、遥测。
- 自动删除原文件；转换只新建输出，绝不删除输入。
- 视觉像素级还原、动画、图表数据重建和嵌入对象内容提取。

## 5. 验收

- 含有效、冲突和损坏文件的队列可完成，其他有效项不受单项失败影响。
- 不覆盖已有输出，取消和失败后无最终半成品目录。
- 结果页计数与每项状态一致，受控打开操作仅指向本次输出。
- Obsidian frontmatter 可被 YAML 解析，标签与来源链接经过校验且不含绝对路径。
- 每个新增兼容性能力都附有无敏感数据的回归样本、预期结构与预期警告。
