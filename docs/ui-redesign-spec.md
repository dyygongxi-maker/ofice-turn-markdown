# 桌面工作台 UI 重构规格

**状态：** 已确认方案，尚未实施  
**日期：** 2026-09-04  
**目标版本：** v0.4（建议）  
**目标入口：** `python -m office_to_markdown`

## 1. 目标

在不改变转换能力、输出协议、安全边界、批处理顺序和发布技术栈的前提下，重构桌面界面的信息架构与实现方式，使它更适合长期维护、批量操作、键盘使用、高 DPI 缩放和后续扩展。

本次是 UI 宿主内部重构，不是转换产品功能升级。

## 2. 用户与核心任务

主要用户是需要在 Windows 本机将 DOCX、PPTX、XLSX 批量归档为 Markdown 的个人用户。界面属于 Operate 模式，首要目标是让用户清楚、快速、安全地完成：

```text
添加文件或扫描文件夹
  -> 确认文件队列
  -> 选择输出位置和可选规则
  -> 开始顺序转换
  -> 查看结果并打开受控输出或报告
```

成功标准：

- 首次打开后 5 秒内能识别“添加文件”是第一步。
- 用户无需记忆上一步信息即可确认输入、输出规则和当前状态。
- 20 个以上文件时队列仍可滚动、选中和查看状态。
- 所有既有业务选项仍以相同值构造 `ConversionOptions`。
- 转换线程、取消边界、错误隔离、输出路径和隐私行为不变。

## 3. 硬性边界

### 3.1 必须保持不变

- 仅支持 `.docx`、`.pptx`、`.xlsx`。
- 支持多文件选择和文件夹扫描，重复文件不重复加入。
- 批处理按队列顺序单线程执行。
- 取消只在当前文件完成后阻止剩余项目开始。
- 已存在同名输出目录时跳过，不覆盖。
- Obsidian、frontmatter、标签、原文件相对链接和原文件复制的现有规则。
- PPTX 每页 PNG 和版式 PDF 的显式选择及 WPS 优先、PowerPoint 后备策略。
- 所有文件只在本机处理；不新增网络、遥测、账户或云能力。
- “打开输出”和“打开报告”只能使用本次转换返回的受控路径。
- Python 3.13、Tkinter/Tcl-Tk、PyInstaller、Inno Setup 构建链。

### 3.2 明确不做

- 不迁移 PySide6、Electron、Tauri、WPF、WinUI 或浏览器宿主。
- 不新增第三方 UI 依赖、图标依赖或字体下载。
- 不新增拖放、文件移除、队列排序、设置页、主题切换、最近记录等功能。
- 不修改解析器、Markdown 输出、转换报告或目录结构。
- 文件夹扫描默认不包含子文件夹；该产品决定已在 Task 0 单独确认，不作为视觉重构的一部分改变。

## 4. 设计方向

### 4.1 结构原则

采用紧凑型 Windows 桌面工作台：文件是主对象，设置是辅助对象，执行动作固定在底部。默认窗口仍为 `1280x800`，最小窗口暂时保持 `1040x760`，除非真实布局验证证明可安全降低。

```text
┌──────────────────────────────────────────────────────────────┐
│ 廾匸转换                    本地处理，不上传文件              │
├──────────────────────────────────┬───────────────────────────┤
│ 文件队列                         │ 转换设置                  │
│ [添加文件] [扫描文件夹] □子目录  │ 输出位置                  │
│                                  │ [路径____________] [浏览] │
│ 20 个文件                        │ [设为默认]                │
│ ┌──────────────────────────────┐ │                           │
│ │ 文件名 | 类型 | 大小 | 状态 │ │ Obsidian 归档            │
│ │ ...                          │ │ □ 启用 Obsidian 模式      │
│ └──────────────────────────────┘ │ Vault / 标签 / 来源选项   │
│                                  │                           │
│ 选中项结果与安全错误摘要         │ PowerPoint 视觉附件       │
│ [打开输出] [打开报告]            │ □ 每页 PNG  □ 版式 PDF    │
├──────────────────────────────────┴───────────────────────────┤
│ 状态摘要                         [取消队列] [开始转换]       │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 视觉原则

- 使用系统字体栈，中文优先采用 Windows 可用字体；不得依赖未随应用分发的 `Noto Sans SC`。
- 页面采用中性浅灰，内容面板为白色，主色只用于主操作、焦点和运行状态。
- 成功、警告、失败、等待状态沿用绿、橙、红、灰语义，但不能只靠颜色表达。
- 面板圆角或边框保持克制；控件高度统一为 32-36px。
- 同屏只有一个高权重主按钮：“开始转换”。
- 禁用控件仍需可辨识文字，不使用过低对比度。
- 不把页面区块全部做成嵌套卡片；右侧使用分组标题和分隔线。

## 5. 组件与职责

目标目录：

```text
src/office_to_markdown/ui/
├── __init__.py
├── main_window.py       # 根窗口、布局编排、任务生命周期
├── state.py             # UI 状态与领域选项映射
├── theme.py             # ttk 样式、颜色、字号、间距令牌
├── queue_panel.py       # 文件队列、选择、结果摘要
├── settings_panel.py    # 输出目录、Obsidian、PPTX 设置
└── status_bar.py        # 全局状态、开始和取消动作
```

原 [app.py](../src/office_to_markdown/app.py) 在迁移完成后只保留兼容导出和 `main()` 入口，避免现有导入路径立即失效。

### 5.1 `UiState`

`UiState` 是界面状态的单一来源，建议保存：

- 输出目录文本。
- 标签文本、Vault 路径。
- 递归、Obsidian、来源链接、复制源文件、PNG、PDF 布尔值。
- 当前源文件有序列表。
- 以规范化路径为键的结果映射。
- 当前选中项。
- 当前任务阶段：`idle | running | cancelling | completed`。
- 用户可见状态摘要。

`UiState` 不读取 Office 文件、不执行转换、不直接打开路径。

### 5.2 `SettingsPanel`

负责把当前控件值转换为 `ConversionOptions`。验证规则继续复用 `validate_tags` 和现有路径检查；不得在组件中复制安全校验逻辑。

依赖关系：

- Obsidian 关闭：标签、Vault、来源链接、复制源文件区域禁用。
- Obsidian 开启且标签为空：执行时仍采用 `office-import`。
- 添加原文件链接：执行前必须存在 Vault 根目录。
- 复制原文件：只有 Obsidian 开启时可用。
- PPTX PNG/PDF 与 Obsidian 相互独立。

### 5.3 `QueuePanel`

优先使用 `ttk.Treeview` 表达队列。建议列：

| 列 | 内容 | 约束 |
| --- | --- | --- |
| 文件 | 文件名 | 可伸缩，长名称截断但保留完整值供详情显示 |
| 类型 | Word / PowerPoint / Excel | 固定宽度 |
| 大小 | 本地文件大小 | 固定宽度，读取失败显示“未知” |
| 状态 | 等待、转换中、完成、警告、失败、跳过、取消 | 文本加语义色 |

队列必须保持 `self.sources` 的原始顺序，不允许 Treeview 的视觉排序改变实际处理顺序。

### 5.4 `StatusBar`

- `idle`：开始按钮只在队列非空且输出目录可验证时可用；取消禁用。
- `running`：开始禁用；取消可用；设置与导入操作禁用。
- `cancelling`：取消按钮禁用并显示“当前文件完成后停止”。
- `completed`：开始可再次使用；结果操作根据选中项启用。

## 6. 状态矩阵

| 场景 | 主按钮 | 取消 | 设置 | 结果操作 | 状态提示 |
| --- | --- | --- | --- | --- | --- |
| 空队列 | 禁用 | 禁用 | 可编辑 | 隐藏或禁用 | 尚未添加文件 |
| 有队列、无有效输出目录 | 禁用 | 禁用 | 可编辑 | 依结果决定 | 请选择输出目录 |
| 可开始 | 启用 | 禁用 | 可编辑 | 依结果决定 | N 个文件等待处理 |
| 转换中 | 禁用 | 启用 | 禁用 | 只读 | 正在处理 i/N |
| 请求取消 | 禁用 | 禁用 | 禁用 | 只读 | 当前文件完成后停止 |
| 已完成 | 启用 | 禁用 | 可编辑 | 成功/警告项可用 | 成功/警告/失败等汇总 |
| 批处理异常 | 启用 | 禁用 | 可编辑 | 依已有结果决定 | 安全、通用错误摘要 |

## 7. 键盘与可访问性

- 使用真实 `ttk.Button`、`ttk.Checkbutton`、`ttk.Entry` 和 `ttk.Treeview`，不以 Canvas 命中区替代控件。
- Tab 顺序按“导入 -> 队列 -> 输出 -> 可选设置 -> 结果 -> 开始/取消”组织。
- Space 激活复选框，Enter 激活当前按钮，方向键移动队列选择。
- 必须有可见焦点，不得仅依赖 hover。
- 状态变化同步到可聚焦的文本区域；错误仍使用原生对话框，并保留安全摘要。
- 在 100%、125%、150%、200% Windows 缩放下验证文字不重叠。
- 文件状态必须同时使用文字和颜色。

## 8. 保持兼容的接口

重构期间以下调用边界不能改变：

```python
discover_sources(directory: Path, recursive: bool) -> tuple[Path, ...]

BatchConversionService.convert(
    sources: tuple[Path, ...],
    output_parent: Path,
    options: ConversionOptions,
    on_item: Callable[[BatchItem], None],
) -> BatchResult
```

UI 必须继续通过线程安全队列把后台事件送回 Tk 主线程。后台线程不得操作 Tk 控件。

## 9. 测试与验收

### 9.1 自动化

- `UiState` 初始值与状态转换。
- 所有 UI 选项到 `ConversionOptions` 的一一映射。
- Obsidian 依赖项启用/禁用逻辑。
- 添加文件去重且保持顺序。
- `BatchItem` 事件更新正确队列项，不改变其他项。
- 选中成功/警告项时结果操作可用；失败、等待项不可用。
- 开始、运行、请求取消、完成和异常后的控件状态。
- 默认尺寸和最小尺寸下左右区域、底栏不重叠。
- 20、100、1000 项的队列填充测试不执行真实转换。
- 既有转换、批处理、安全和发布脚本测试全部继续通过。

### 9.2 手工桌面验证

- 空状态、单文件、混合格式、多文件、输出冲突、部分失败和取消。
- 长中文/英文文件名、长路径、不可读取大小。
- Windows 键盘导航和焦点顺序。
- Windows 100%、125%、150%、200% 缩放。
- `1280x800`、`1040x760`、最大化和窗口还原。
- WPS/PowerPoint 不可用时，视觉导出失败仍不影响 Markdown 主流程。

### 9.3 发布验证

```powershell

.\.venv-ui\Scripts\python.exe -m ruff check .
```

正式验收必须启动新生成的 exe 和安装后的程序，不能只以构建成功作为发布成功。

## 10. 开放决策

### OD-001：文件夹扫描默认不递归

**状态：** 已确认，2026-09-04。

用户确认默认不包含子文件夹。`MainWindow.recursive` 的初始值为 `False`；扫描文件夹时仍允许用户在操作前显式勾选“包含子文件夹”。该行为在 Task 0 单独完成并由初始化测试保护，不属于后续视觉重构的隐式变化。

## 11. 完成定义

- 所有既有功能与安全合同保持一致。
- UI 模块已拆分，`app.py` 不再承担全部绘制和状态职责。
- 主要交互使用原生 Tk/ttk 控件，键盘和焦点行为可验证。
- 自动化、Ruff、真实窗口、构建、安装和卸载验证完成。
- `PROJECT.md`、`ARCHITECTURE.md`、`DECISIONS.md`、`CHANGELOG.md`、`docs/problems.md` 与实际实现一致。
- 实现过程没有提交输入文档、转换输出、凭据或个人数据。
